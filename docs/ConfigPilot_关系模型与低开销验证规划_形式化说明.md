# 服务网格配置验证的统一语义模型与低开销验证规划

更新日期：2026-11-17。

本文给出面向服务网格配置验证的方法定义。接口与支持范围见 [实现核对表](IMPLEMENTATION_STATUS.md)。

方案以统一语义模型连接声明配置、数据面规则和运行行为，将验证需求转为完整的验证义务，再组织探针生成、执行与证据采集。PAOC 描述单策略属性，规则顺序、引用和联合约束等关系用于补充组合行为的解释。

## 1. 问题边界与符号

设声明配置为 \(C^{\mathrm{ref}}\)，被测数据面状态为 \(C^{\mathrm{run}}\)。二者分别构造模型，声明参照及其版本在一次验证中固定；不能根据错误或变异后的数据面重新生成正确答案。

用 \(\Gamma\) 表示本文支持的语义片段，包括策略种类、参数范围、关系解释及证据契约。\(\Gamma\) 是方法的适用范围，不是在 PAOC 之外新增一个重复的策略作用范围维度。

| 符号 | 含义 |
|---|---|
| \(\pi_i\) | 单条策略单元，采用 PAOC 表示 |
| \(q\) | 带身份的规则，例如某 VS 的一条 HTTP 路由 |
| \(z\) | 配置资源或目标资源，例如 VS、DR、Service |
| \(r\) | 带类型、参与者和适用条件的语义关系 |
| \(x,s\) | 请求输入及抽象运行状态 |
| \(o_i\) | 逻辑验证义务，不等同于一次物理探针执行 |
| \(p_j\) | 候选探针，可以是一条请求或有明确负载约束的请求批次 |
| \(e\) | 本次执行收集到的证据集合 |
| \(\bot\) | 未支持、未解析或无法确定，不能解释为不成立或不存在 |

## 2. 统一语义模型

### 2.1 单策略语义保持 PAOC

每条策略表示为：

\[
\pi_i=\langle P_i,A_i,O_i,C_i\rangle.
\tag{1}
\]

其中，\(P_i\) 是匹配或触发谓词，\(A_i\) 是处理动作，\(O_i\) 是作用范围，\(C_i\) 是行为约束和参数。命名空间、目标服务、端口、Gateway、subset 及适用的工作负载选择条件仍属于作用范围及其绑定信息，不重复增加一个“上下文”属性。

同时为每个策略保存非语义元数据：唯一身份、所属规则、来源资源、字段位置、层次与快照版本。元数据不是 PAOC 的第五个维度，其作用是避免按服务聚合后丢失具体规则归属，并支持追溯和跨层关联。

### 2.2 用带类型的关系扩展单策略集合

定义统一模型为：

\[
\mathcal M^{\ell}=\langle V^{\ell},\mathcal R^{\ell};\Sigma_\Gamma\rangle,
\qquad
V^{\ell}=\Pi^{\ell}\uplus Q^{\ell}\uplus Z^{\ell}.
\tag{2}
\]

\(\ell\) 表示声明层或数据面层；\(\Pi\)、\(Q\)、\(Z\) 分别为策略、规则和资源节点；\(\uplus\) 表示节点类型相互区分。策略节点携带 PAOC 属性。\(\Sigma_\Gamma\) 是在支持片段内解释节点及关系的语义规则。

这种定义没有改变 PAOC，而是将原来的“策略属性集合”扩展为“策略属性与关系共同构成的语义图”。三个类型的节点也可以在实现中用独立列表、身份引用和索引保存，不要求存入图数据库。

关系采用带类型的有向超边表示：

\[
r=\langle t,\boldsymbol v,\varphi\rangle,
\qquad \boldsymbol v\in V^{+}.
\tag{3}
\]

\(t\) 为关系类型，\(\boldsymbol v\) 是有序参与者列表，\(\varphi\) 为关系适用条件。多参与者关系允许直接描述共同时间预算等联合约束，不要求将其全部降为两两关系。来源、语义版本及支持状态作为关系元数据保留。

| 关系类型 | 表达内容 | 在验证中的用途 |
|---|---|---|
| \(\operatorname{precedes}(q_a,q_b)\) | 同一个有序选择组内，\(q_a\) 先于 \(q_b\) | 分析遮蔽并寻找实际可激活请求 |
| \(\operatorname{attached}(\pi_i,q)\) | 策略属于规则 \(q\) | 保留共同生效的处理指令 |
| \(\operatorname{references}(v,z)\) | 节点显式引用另一个资源或目标 | 解析目标与配置依赖 |
| \(\operatorname{overrides}(v_a,v_b)\) | 局部设置覆盖或继承基础设置 | 在语义已知时求最终参数 |
| \(\operatorname{joint}(\pi_1,\ldots,\pi_k)\) | 多策略受到共同约束 | 生成交互义务、限制不安全复用 |
| \(\operatorname{shortcuts}(\pi_a,\pi_b)\) | 前一动作可能使后一动作不再执行 | 区分配置存在与行为实际发生 |

例如，retry 与 timeout 的共享预算是 joint 的具体类型；fault 可能提前终止请求，是 shortcuts 的具体类型。

对每个关系标注 \(\kappa(r)\in\{\mathrm{interpreted},\mathrm{retained},\mathrm{unresolved}\}\)。只有前者在 \(\Gamma\) 内具有可执行解释；另外两类保留为不确定性及前提约束。没有提取到关系，不等于已经证明策略之间不存在关系。

### 2.3 关系共同决定有效行为

设 \(m_q(x,s)\) 表示请求和状态满足规则 \(q\) 的匹配条件及作用范围。对 first-match 选择组，有效选择条件为：

\[
\operatorname{Select}_q(x,s)
=m_q(x,s)\land
\bigwedge_{q'\prec q}\neg m_{q'}(x,s).
\tag{4}
\]

这里的前序关系只在具有明确顺序语义的同一选择组内使用，不能将不同 VS 的局部索引拼接成全局优先级。前序谓词或跨资源竞争无法解释时，选择结果保留未知。

式（4）描述规则是否被选中，不表示该规则附着的每一种行为都已触发。例如，重试还需要可重试的上游失败；被选中的路由不等于发生了重试。

在支持范围内，模型通过 \(\Sigma_\Gamma\) 解释为请求、状态到规范化可观测行为的映射：

\[
\llbracket\mathcal M\rrbracket_\Gamma:(x,s)
\longmapsto\mathcal B_\Gamma\cup\{\bot\}.
\tag{5}
\]

可观测行为包括目标选择、报文变换、上游尝试序列、时间约束和状态变化。对加权分流等随机行为，应在 \(\mathcal B_\Gamma\) 中表示行为分布及相应参数，不能仅用“可能到达的目标集合”代替比例语义。

因此，两个模型即使具有相同 PAOC 多重集合，也可能因顺序、覆盖或联合约束不同而具有不同语义。

### 2.4 跨层一致性采用有效行为比较

设 \(\mathcal D\) 为支持范围内的请求与初始抽象状态域。将层间实现细节规范化后，理想的跨层语义等价定义为：

\[
\mathcal M^{\mathrm{ref}}\equiv_{\Gamma,\mathcal D}
\mathcal M^{\mathrm{run}}
\iff
\forall(x,s)\in\mathcal D:\;
\llbracket\mathcal M^{\mathrm{ref}}\rrbracket_\Gamma(x,s)
=\llbracket\mathcal M^{\mathrm{run}}\rrbracket_\Gamma(x,s)
\ne\bot.
\tag{6}
\]

规范化须对齐服务身份、协议字段及语义单位，但不要求生成规则与源规则逐条同构。多条实现规则可以共同实现一条声明规则。

该定义同时排除期望行为缺失与额外非预期有效行为；不把不可达冗余条目直接等同于运行差异。若任一侧为未知，不能宣称已证明等价。

式（6）是方法的判定目标，不是声称当前工具已经穷尽无限输入或所有 Istio 语义。实际检查在受支持且可判定的分区、约束和动态见证上开展。有限探针一致不能证明全域等价；随机行为的有限样本检查也不能证明分布完全相等。若采用容差或统计判定，须另行声明相应标准，不能将它当作式（6）的严格证明。

## 3. 从模型生成验证义务

### 3.1 四维场景与验证义务分离

保留原有 if、what、when、where 场景设计。四维用于生成需要验证的行为，不直接决定哪些物理探针可以删除或合并。

模型生成验证义务集合：

\[
\mathcal O
=\mathcal O_{\mathrm{policy}}
\cup\mathcal O_{\mathrm{relation}},
\qquad
o_i=\langle G_i,H_i,E_i,K_i\rangle.
\tag{7}
\]

\(G_i\) 为设计的触发条件，\(H_i\) 为目标行为断言，\(E_i\) 为证据需求，\(K_i\) 为执行前提，包括参照版本、阶段、负载及隔离要求。身份、来源和四维场景取值作为元数据保存。

策略义务检查单个策略的行为；关系义务检查受支持关系的可观测后果。例如，顺序关系可生成重叠请求下的优先选择义务，共享时间预算可生成请求结束时间和重试尝试的联合义务。不是每个引用边都必须生成一个单独动态探针，某些关系只参与前提检查或依赖分析。

### 3.2 使用定向行为依赖闭包

对义务来源集合 \(S_i\)，定义行为依赖切片为：

\[
D_i=\operatorname{lfp}_{D}
\left(S_i\cup\operatorname{Deps}_{\Sigma_\Gamma}(\mathcal M,D)\right).
\tag{8}
\]

依赖传播方向由关系语义决定：后序规则纳入可能遮蔽它的前序规则；策略纳入共同生效指令和引用目标；联合约束纳入相关参与者。普通引用不能随意反向扩张为所有引用者。

未知依赖进入不确定性记录，不能从切片中悄悄消失。切片用于组织依赖和复用计算，不允许在删除其他竞争规则后宣布当前规则可达；候选激活检查仍保留完整选择与跨资源竞争上下文。

## 4. 低开销验证规划

### 4.1 默认独立，满足条件才允许探针复用

首先为具备执行能力的义务保留独立探针基线。“独立”表示每项义务有自己的执行与判定依据，不表示从环境删除其他策略，也不表示所有探针必须串行。

候选探针 \(p_j\) 包含请求或批次、阶段、触发后端行为及负载，拟支持义务组 \(I_j\subseteq\mathcal O\)。对整个义务组定义准入：

\[
\operatorname{Adm}_\Gamma(p_j,I_j\mid\mathcal M)
=\operatorname{TriggerPreserved}
\land\operatorname{ContextPreserved}
\land\operatorname{EvidenceSufficient}
\land\operatorname{RuleApplicable}.
\tag{9}
\]

各条件含义如下：

1. **TriggerPreserved：** 候选请求及后端行为满足各义务所需的触发设计，且不存在已知遮蔽或提前截断。
2. **ContextPreserved：** 整个关系上下文中的选择、作用范围、有效参数、阶段、负载和状态前提得到保持。
3. **EvidenceSufficient：** 执行预期能产生各义务判定所需的完整、可归因证据；允许同一记录支持多个断言。
4. **RuleApplicable：** 候选组落在明确支持、具有说明及验证依据的复用规则适用范围内，且没有未解析的相关关系阻止准入。

准入检查针对完整组合，不从两两兼容推出任意大组合兼容。规划中的“预期可触发、可采证”也不保证运行中必然获得证据，执行后仍须再次判定。

定义三值覆盖关系：

\[
W_{ij}=\begin{cases}
1,&o_i\in I_j\ \land\operatorname{Adm}_\Gamma(p_j,I_j\mid\mathcal M)=\mathrm{true},\\
0,&o_i\notin I_j\ \text{或存在明确不满足准入条件的依据},\\
\bot,&\text{语义、触发、适配或证据能力尚不能确定}.
\end{cases}
\tag{10}
\]

优化只使用值为 1 的覆盖关系，不把未知解释成可覆盖。已知不同有效规则且无法由同一执行触发时，应明确记录不兼容；适配能力未实现则记录未知，两者不混为一类。

### 4.2 覆盖规划不删除未支持义务

设 \(\mathcal O_{\mathrm{exec}}=\{o_i:\exists j,W_{ij}=1\}\)，\(\mathcal O_{\mathrm{pending}}=\mathcal O\setminus\mathcal O_{\mathrm{exec}}\)。以探针成本 \(c_j>0\) 为权重，可将探针选择表示为：

\[
\min_{z_j\in\{0,1\}}\sum_j c_jz_j,
\qquad
\text{s.t.}\quad
\sum_{j:W_{ij}=1}z_j\ge1,
\quad\forall o_i\in\mathcal O_{\mathrm{exec}}.
\tag{11}
\]

\(\mathcal O_{\mathrm{pending}}\) 继续留在报告和覆盖全集中。没有可信适配器时，应保留未规划或未判定状态，而不是强行生成一个无触发保证的独立探针。

实际可采用“每单位成本覆盖最多未覆盖义务”的贪心策略。当前实现主要取 \(c_j=1\)，优化的是逻辑探针数量，不自动等于最小实际请求量；批量分流和压力探针必须另外统计实际请求数。

该集合覆盖模型是探针选择子问题，不声称已联合求解采集、容量和总完成时间的全局最优方案。

### 4.3 采集共享与证据复用独立定义

设采集任务 \(a_k\) 的观测能力为 \(\operatorname{Cap}(a_k)\)。用 \(a_k\succeq E_i\) 表示其来源、选择条件、字段、时间窗口、粒度及完整性足以满足义务的证据需求。共享采集的条件为：

\[
\operatorname{Share}(a_k,I)
\iff\forall o_i\in I:\;a_k\succeq E_i
\ \land\operatorname{Attributable}(a_k,I).
\tag{12}
\]

例如，一次批量读取取得多条按请求 ID 关联的回执，可分别用于多个独立探针；同一条回执也可同时支持目标、Header 和改写断言。共享采集不会消耗证据，同一记录可以被多个义务引用。

采集兼容不意味着探针可合并；使用不同证据字段也不是安全合并的充分条件。仅给请求加标签，而遥测没有保留该标签或其他关联信息时，不能认为观测已隔离。

### 4.4 冲突感知调度独立定义

每个执行任务具有资源足迹 \(F_j=\langle R_j,W_j,Z_j,L_j,B_j\rangle\)：配置读取集、写入集、共享状态域、负载需求和证据归因要求。

两个任务的配置冲突为：

\[
\operatorname{CfgConflict}(a,b)
\iff W_a\cap(R_b\cup W_b)\ne\varnothing
\ \lor\ W_b\cap R_a\ne\varnothing.
\tag{13}
\]

对于拟同时运行的任务集合 \(J\)，整体并发许可为：

\[
\operatorname{Parallel}_\Gamma(J)
=\operatorname{NoCfgConflict}(J)
\land\operatorname{StateCompatible}_\Gamma(J)
\land\operatorname{EvidenceAttributable}_\Gamma(J)
\land\operatorname{WithinBudget}(J).
\tag{14}
\]

StateCompatible 要求不破坏相互的共享状态前提，或已有专门的联合执行规则；WithinBudget 检查整个并发集合的总负载。不能只做两两检查后忽略组合负载。

调度器先预留资源再分配 worker，冲突任务停留在待运行队列，不占执行线程。等待证据时可以让出线程，但配置和状态预留保持到必要的观测、恢复及上游收尾结束。

资源预留只协调本调度器管理的任务，不自动阻止集群外部更新；运行仍需版本和代次检查。版本变化或证据陈旧时不能继续判通过。

探针复用与并发许可是两种不同关系：不复用的探针可以并发，复用后的任务仍可能与其他任务共享状态而冲突。

### 4.5 受控后端降低触发与配置变更成本

探针执行可指定后端行为契约 \(b(x,\mathrm{requestId},s)\)，例如同一请求前 \(N\) 次返回 503、后续返回 200，或保持响应一段时间。契约由冻结参照推导，不覆盖被测代理策略。

后端按请求身份隔离触发状态，并记录实际到达事件；重试仍由真实代理完成。执行阶段可以有 \(W_j=\varnothing\)，从而消除式（13）中的配置写入冲突，但并不自动使式（14）成立：连接池、限流桶和实例摘除状态仍可能共享。

受控后端不改变目标配置应在何处执行这一事实。网关策略须经过相应网关；网格内部策略须经过相应工作负载代理。隔离后端实验不能直接冒充原业务工作负载、身份和拓扑的完整验证。

后端准备、必要配置切换和清理成本仍需计入。共享进程、多个逻辑目标和少量测试槽位可以摊薄成本，但不能假设每个用例都需要或都不需要独立实例。

## 5. 执行判定与检错保持

### 5.1 证据驱动的三值判定

对义务 \(o_i\)，设 \(Q_i(e)\) 表示证据足以支持该义务的一次可靠判定，包括参照身份、运行与请求关联、配置代次、时间新鲜度及必需字段完整性。定义：

\[
V_i(e)=\begin{cases}
\mathrm{PASS},&Q_i(e)\land H_i(e)=\mathrm{true},\\
\mathrm{FAIL},&Q_i(e)\land H_i(e)=\mathrm{false},\\
\mathrm{INCONCLUSIVE},&\text{其他情况}.
\end{cases}
\tag{15}
\]

对多条可用执行记录，可信反证优先于支持证据；局部无关信息缺失不应抹去已经充分的反证。\(Q_i\) 按义务定义，不要求收集所有可能的遥测。

重要的是：\(Q_i\) 不包含“被测策略已经正确生效”这一循环前提。实际目标错误时，完整且可归因的目标证据应使路由义务 FAIL，不能因为预期规则未激活就一律改为未判定。对于依赖正确目标上下文的 Header 义务，则可能因上下文缺失保留 INCONCLUSIVE。

规划可覆盖不等于运行完成。报告至少分别给出：

\[
\operatorname{PlannedCoverage}
=\frac{|\mathcal O_{\mathrm{exec}}|}{|\mathcal O|},
\qquad
\operatorname{AssessmentCompletion}
=\frac{|\{o_i:V_i\in\{\mathrm{PASS},\mathrm{FAIL}\}\}|}{|\mathcal O|}.
\tag{16}
\]

未支持及未判定义务均保留在原义务全集中；不得以移除分母制造覆盖保持或准确率提高。

### 5.2 正交与检错能力采用条件化表述

本文不再根据配置功能名称或观测字段互斥默认判定正交。若保留“正交”术语，应将其限定为：在给定模型、触发方式、负载、状态和证据契约下，组合执行不破坏各项验证行为和判定依据的条件性非干扰。

顺序与优先级、作用范围与覆盖、多资源联合约束分别进入式（9）的触发和上下文保持检查；证据可区分性与完整性进入证据充分性；检错能力保持还需要额外的规则论证与缺陷实验，不能由覆盖矩阵直接推出。

对声明的故障集合 \(\mathcal F\)，令 \(\operatorname{Fail}_{\mathrm{base}}(f)\) 与 \(\operatorname{Fail}_{\mathrm{plan}}(f)\) 分别为独立基线和规划方案检出的失败义务集合。不降低既有检出能力的目标为：

\[
\forall f\in\mathcal F:\quad
\operatorname{Fail}_{\mathrm{base}}(f)
\subseteq\operatorname{Fail}_{\mathrm{plan}}(f).
\tag{17}
\]

还应对正常配置评价是否产生新误报，不能以额外错误判定满足式（17）。实现对照可采用更强的逐义务三值一致性：

\[
\forall f\in\mathcal F_{\mathrm{test}},\ \forall o_i\in\mathcal O:\quad
V_i^{\mathrm{base}}(f)=V_i^{\mathrm{plan}}(f).
\tag{18}
\]

\(\mathcal F_{\mathrm{test}}\) 是明确构造和执行的有限缺陷集。式（18）在该集合上成立，是有限范围内的实验结论，不是针对任意 Istio 策略和任意故障的普遍定理。统计探针还应固定样本规则和容差，并解释随机性对逐次结果的影响。

### 5.3 成本指标应分别报告

规划的总体目标可用请求、采集、配置变更和总完成时间的加权成本概括：

\[
C(\mathcal P)=
\alpha N_{\mathrm{req}}
+\beta N_{\mathrm{collect}}
+\gamma N_{\mathrm{write}}
+\delta T_{\mathrm{wall}},
\qquad \alpha,\beta,\gamma,\delta\ge0.
\tag{19}
\]

该式表达多来源开销，不意味着当前实现已经联合最优化这些指标。论文应分别报告实际请求减少率、采集量、配置写入数、墙钟时间、CPU 时间、峰值内存，以及首次准备和重复执行成本，避免用探针数直接代替所有收益。

## 6. 两个贯穿示例

### 6.1 同一路由的目标与 Header 检查

一条路由同时包含目标选择和 `x-source` 设置。模型中两条策略通过 attached 关联同一规则。若请求能实际选中该规则、没有未知共同指令或相关共享状态，并能取得完整目标与 Header 回执，则一个探针可支持两个义务；两项断言分别判定。

两项证据不需要彼此互斥，目标身份与 Header 可以来自同一条记录。这体现的是行为和证据复用，而非“配置功能天然正交”。

### 6.2 重试恢复与总超时

同一路由上的 retry 和 timeout 通过共享预算关系关联。重试恢复探针需要失败后成功；总预算探针需要足够慢的响应暴露截止约束。二者触发条件不一定兼容，不能仅因所属阶段不同就合并。

因此保留不同探针，但可复用后端程序、按请求 ID 读取的回执能力，以及兼容的采集任务。若存在共同连接池等状态，还需单独检查并发许可。

## 7. 可直接用于论文的方法概述

**统一语义模型。** 我们保留 PAOC 四元组描述单条策略的谓词、动作、作用范围与行为约束，并通过具有身份和来源的策略、规则及资源节点，显式表示选择顺序、规则附着、引用绑定、继承覆盖及联合约束。模型在声明的支持片段内根据关系解释策略的有效组合行为，避免将属性集合相同误判为语义相同。跨层检查以规范化有效行为的一致性为目标，并显式保留未支持语义和未解析关系。

**低开销验证规划。** 我们将四维测试场景首先转化为包含触发条件、行为断言、证据需求与执行前提的验证义务，再通过定向依赖分析构造候选探针。规划默认保留独立验证，仅在完整关系上下文中确认触发、有效配置、执行前提及证据能力兼容，且满足受支持复用规则时允许一个探针支持多个义务。探针选择、采集共享及冲突感知调度分别优化重复执行、重复观测与等待开销；执行后依据可归因证据逐义务输出通过、失败或未判定。覆盖义务保持与有限缺陷集上的判定一致性分别评价，不将规划覆盖表述为普遍的检错保证。
