# 基于关系语义模型的验证规划：设计草案

状态：总体设计。已接入 parser 关系产物、显式义务规划入口与证据判定，完成受控串行及并发实验，并增加可选计算进程后端；完整关系语义、生产采集适配和默认生产流程的完整调度联动仍待完成。2026-11-06。实际接口与限制见 [实现说明](RELATIONAL_VALIDATION.md)。

目标：优先修复用例约简的覆盖与判定问题，再优化共享采集、探针复用和并发。方案以跨层统一语义模型和验证义务为基础，组织探针生成、执行与证据采集。

当前方案统一称为“基于关系语义模型的验证规划”。if、what、when、where 继续作为场景描述维度；覆盖决策、证据共享、探针复用和并发许可分别定义。历史实验及旧接口名称保留用于追溯。

## 1. 三项独立优化

```text
统一语义参照模型 M_ref = ⟨Π, R; Σ⟩
        ↓
策略义务 + 关系义务 + 行为依赖切片
        ↓
候选探针及覆盖见证
        ↓
覆盖规划（保留全部验证义务）
        ↓
分别检查采集共享 / 探针复用 / 并发条件
        ↓
执行、确认实际触发、检查证据质量
        ↓
逐义务判定，记录成功、失败和未能判定的原因
```

采集兼容不推导探针可复用；探针可复用不推导任务可以并发。未知条件保留独立探针和必要隔离。初期全部串行，避免并发干扰准确性基线。

## 2. 参照模型与被测状态分离

`M_ref` 表达固定的验证意图；`M_run` 表达本次运行采集到的有效配置和环境状态。两者分别保存版本、资源身份、快照摘要及语义解释版本。缺陷变异实验固定 `M_ref`，只改变 `M_run`，不根据变异后的状态重新生成正确答案。

模型的未知关系、未支持字段、未解析引用必须保留并标明原因。不能将“没有提取到关系”解释为“没有关系”。参考模型不完整时，禁止据此批准探针替代。

当前动态入口从 aligned_semantic 的 matched/partial_matched 元组生成用例。后续需要由 parser 产物显式保留义务来源和依赖上下文：即使前序规则不属于当前动态可执行元组，也可能遮蔽后序规则，不能在切片中丢失。未对齐项可以作为静态缺陷或不可执行义务记录，不能直接套用已对齐元组的动态期望，也不能从覆盖分母静默删除。

动态模块消费 parser 落盘的关系模型，不重新解析 YAML。`graph_data` 中的资源关联边不自动等价于带完整运行语义的关系模型。

## 3. 验证义务与触发语义

保持 `o_i = ⟨G_i,H_i,E_i,K_i⟩`，并增加身份、来源及可执行性诊断。覆盖全集为策略义务与关系义务的并集。

| 字段 | 内容 |
|---|---|
| identity | obligation_id、来源规则/关系、四维取值、M_ref 摘要 |
| G | 触发输入、预期激活条件、所需触发见证；区分可控输入与被测行为 |
| H | 独立断言、判定器版本、阈值和边界要求 |
| E | 所需字段、归因方式、新鲜度、样本量、去重、缺失与截止规则 |
| K | 配置依赖、阶段、负载、初始状态、恢复要求 |

必须区分三种情况：

1. 输入或环境准备失败，未能建立有效试验：INCONCLUSIVE，保留未完成义务。
2. 参照模型预期某规则激活，输入和配置生效条件已确认，但可信证据显示它被错误的规则截获：对相应选择/优先级义务判 FAIL，不能仅记“未触发”。
3. 参照模型本来就预期某规则被遮蔽：不能声称验证了其实际转发行为；另建遮蔽关系义务。若没有任何合法输入能激活目标规则，记录不可达和关系原因，不能伪造覆盖。

被测结果本身不能成为“必须先成功满足才允许判失败”的前提。证据完整也不等于出现了预期结果；完整的反证能够支持 FAIL。

## 4. 行为依赖切片

`S_i = Slice(M_ref,o_i)` 包含可能影响触发、断言及证据的规则、关系和状态域：前序选择规则、覆盖与继承、资源与子集引用、总时间预算及共享运行状态等。

关系记录需要带选择组、顺序、适用条件和来源；联合预算等多方关系可采用带多个参与者的关系对象，不能假定所有依赖都能用独立二元边表达。

仅当 Σ 已定义同一选择组为按顺序首次命中时，可据其语义推导有效谓词，例如 `p_i AND NOT p_1 ... AND NOT p_(i-1)`，并叠加该组适用范围。不能把该式无条件套到不同选择组或不同资源之间。

切片相交是进一步检查的线索，不自动代表冲突；切片不相交也不能豁免未建模的环境容量约束。

## 5. 候选探针与有依据的覆盖矩阵

探针 `q` 是完整的执行场景，可以包含多次请求、负载和准备/执行/恢复阶段，而非必须是单个 HTTP 请求。对需要基线与高压对照、恢复窗口或统计样本的义务，先构造完整场景，再用于覆盖优化。

每个 `(q,o_i)` 产生 `CoverageDecision`：

```text
decision: eligible | ineligible | unknown
reference_model_hash
probe_hash
obligation_id
precondition_check
trigger_witness_plan
assertion_evaluator
evidence_contract
dependency_slice_ids
reuse_rule_id / applicability_scope / validation_basis
reason
```

只有 eligible 对应 `W_qi=1`。unknown 和 ineligible 均不得授权删除原探针，但分别保留解释，避免把未实现的语义当作已经证明不兼容。

除了逐义务覆盖约束，选择计划还要满足 `Admissible(M_ref,Q')`：实际采用的配置、负载、阶段和证据方案均在允许范围内。若组合过程中改写探针或合并阶段，探针摘要改变，必须重新计算覆盖及许可条件，不能继续使用旧 W。

初期只做保守选择，不引入复杂求解器。先确保覆盖见证可信，再优化成本。允许一个已验证探针支持多个义务，但不能仅因它们字段相同、结果相同或策略标签已存在，就建立覆盖关系。

## 6. 共享证据与逐义务判定

证据记录以 execution_id、request/attempt 身份、观测位置、配置代次、服务实例、阶段及时间为上下文。义务通过引用关联证据；同一记录可以支持多个义务，不因被一个断言使用而被消耗。

不同观测位置看到同一请求，不自动表示发生了重试。请求标识能否贯穿各阶段、能否区分上游尝试，需要实际确认。共享采集前必须验证游标、去重、重启处理、归因与质量条件。

每个运行后结果分别保存：

```text
obligation_id
planned_probe_ids
executed_probe_ids
trigger_assessment
evidence_references
evidence_quality
verdict: PASS | FAIL | INCONCLUSIVE
reason
```

覆盖计数与通过率分离：

- 计划覆盖：存在 eligible 的探针及覆盖见证。
- 评估完成：证据足以给出 PASS 或 FAIL；FAIL 同样是完成了一次有效评估。
- 未完成：准备失败、无法归因、样本不足、未支持或未能执行，分别列原因。

被测错误导致未按预期激活时，优先依据可用反证判相关义务 FAIL；没有足够证据时才归为 INCONCLUSIVE。不能通过只统计成功激活或 PASS 的义务来制造高覆盖率。

## 7. 探针替代规则的实验准入

规则记录完整参与组合、配置/负载/阶段条件、模型与代理版本范围、证据能力、验证依据及失效条件。未知组合保留原探针；两两许可不能拼成完整组合许可。

针对有限缺陷集合 F，固定 oracle 和原验证义务，对比原探针及替代探针的检出结果：

```text
Detect(original, f, o) => Detect(reused, f, o)
```

只对已验证的 F 和适用条件声称检错能力保持。需要正常配置对照，分别报告漏检、误报、证据不足和规则不适用。先修复原判定器，不能以原判定器的错误 PASS 作为替代探针的正确性基准。

## 8. 调度接口与后续生产集成

`Footprint(q)=⟨R_q,W_q,D_q,B_q⟩`，包含依赖稳定的配置、修改的配置、不可隔离的观测/状态域和容量预算。切片用于推导影响范围，运行时还需确认实际资源与环境。

共享 Trace 归因不解除共享连接池、限流或熔断状态约束。配置读写互斥外，需检查运行状态和全组容量预算。等待证据可以释放 worker，但不能提前释放仍支撑义务前提的资源预留。

已有线程就绪队列用于受控并发实验，计算进程只处理不可变模型与证据，不绕开资源锁。默认业务观测互斥与 worker 配置保持原状；生产采集适配及新规划入口的完整调度联动仍需单独验证。接口与实验边界见 [并行说明](PARALLEL_VALIDATION.md)。

## 9. 对照已发现反例的验收

评估时保留独立验证基线，检查以下反例；评估产物在本地单独保存。

| 反例 | 方案的验收要求 |
|---|---|
| 六路由约简后只保留首条，检出 3/18 | 保留六个路由义务；没有替代见证时保留各自探针；固定同一变异集恢复检出 18/18，不要求强行减少探针 |
| 不同 Host/Header/路径被覆盖成一个请求 | 每个义务具备有效输入和对应证据；无法共同触发则分别执行 |
| 重叠前缀 bundle 导致 504 变为 503 | 阻止无依据的打包；任何重排或规则改写都重新检查完整选择语义及预期故障行为 |
| 200ms 总超时遮蔽 retry | 明确区分重试义务与预算交互义务；短预算请求不能替代可检出重试缺陷的独立场景 |
| 无目标证据却路由 PASS | 返回 INCONCLUSIVE；可信错误目标证据返回 FAIL |
| 多位置日志误算重试 | 依请求、尝试和观测位置归因，不能以总日志条数作为充分证据 |
| 超时只判断 504 | 校验义务要求的边界与原因；原因或时间证据不足不能 PASS |
| orthogonal_matching 无判定器 | 不再把标签当作已实现能力；逐义务判定，未支持项显式报告 |

## 10. 实施顺序与产物

1. **义务与串行基线**：parser 产物增加带来源的关系/顺序语义；动态侧增加义务与切片、触发见证、逐义务结果。保留独立探针，修复缺证据仍通过等判定问题。
2. **覆盖决策与有限复用**：增加三态覆盖决策及依据，使用上述固定变异集审查替代规则。所有义务仍然存在于结果中。
3. **共享采集**：按证据合同汇总采集需求，并检查实际归因、去重和质量。此阶段不以共享采集为由解除运行状态约束。
4. **并发调度**：在准确性回归通过后，将 footprint 与容量约束交给调度器，并重复准确性对照。

拟议落盘产物：`validation_obligations.json`、`probe_plan.json`、`coverage_decisions.json`、`obligation_results.json`。均带 schema 与参照模型版本，保留从四维/关系来源到运行证据和最终结果的追溯链。

论文表述限定为：模型给出验证义务及依赖，规划器在明确条件下优化探针与采集，调度器利用实际独立性；完成覆盖由实际证据确认，替代规则的检错保持结论仅覆盖其已论证或已实验验证的范围。
