运行时配置

启动方式

命令行统一入口：python -m configpilot web --port 8080

完整流水线：python -m configpilot run --namespace {{ namespace }}

静态分析

针对所选命名空间，将控制面 YAML 与数据面 Envoy dump 映射到同一套语义元组。图上只显示该命名空间的服务与 Istio 资源。

执行静态分析后，点击节点查看命名空间、声明式配置和数据面规则。

动态验证

把静态对齐得到的期望行为打成探测流量，再对照运行时观测做一致性判定。每条用例都会给出预期行为、实际行为和判定结果。

预期行为 来自 aligned_semantic：路由目标、分流权重、限流、熔断阈值、超时、重试。
实际行为 本次打流观测：状态码、落到的服务/版本、时延、是否出现 429/503/超时。
一致性 实际是否落在预期容差内。跳过的用例（未开高压/故障注入/rollout）不算通过也不算失败。
动态验证开关

路由、分流、限流基线会尽量打入。下面三项关闭时，对应用例会跳过并提示原因。

一致性验证

按所选命名空间对照声明、数据面和运行时。点开一条记录可看 Sdecl / Sdp / Srt 的字段差异；JSON 与独立 HTML 仍可导出。

完整流水线 · 动态验证开关

第二阶段会真正打流。关闭高压/故障注入/rollout 时，熔断、超时、重试、限流高压会跳过。
